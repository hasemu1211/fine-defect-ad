# FineDefect AD

**고해상도 금속 표면 결함 탐지에서 입력 공간 정보, 특징 표현, 실행 백엔드가 결과에 미치는 차이를 두 이상 탐지 파이프라인으로 검증한 프로젝트입니다.**

## 이 프로젝트에서 확인한 것

1. **고해상도 영상에서는 공간 정보 보존이 중요한 개선 지점이었습니다.** 같은 EfficientAD 체크포인트에서 전체 이미지를 256×256로 축소한 기준선보다, 타일 국소 맵과 전체 장면 전역 맵을 결합한 E2-Split의 Image AU-ROC가 `0.595370 → 0.734722`, AU-PRO@0.05가 `0.020582 → 0.132685`로 높아졌습니다. 모델 재학습보다 추론 파이프라인 변경의 효과를 분리해 확인한 결과입니다.
2. **두 모델의 차이는 모든 결함에 균일하지 않았습니다.** SuperADD / DINOv3는 전체 위치화 지표가 높았지만, 동일 불량 이미지 90장을 짝지어 보면 우위가 중간 크기와 낮은 compactness의 결함에서 특히 크게 관측됐습니다. 이는 모델 순위를 정하는 결론이 아니라 서로 다른 특징 표현이 만든 오류 패턴을 설명하는 근거입니다.
3. **배포 최적화와 모델 성능 개선을 분리했습니다.** E2-Split을 TensorRT FP32와 Triton으로 옮겨 대표 이미지 E2E 지연을 `2.4610 → 2.1040초`로 줄이면서 TESTpub 지표가 근접하게 유지되는지 별도로 검증했습니다.
4. **실험과 검증을 하나의 재현 흐름으로 연결했습니다.** 같은 데이터·출력 해상도·평가기, TEST 누수 차단, SHA-256 증거 결속, 변환 전후 parity, 이미지별 오류 분석을 함께 구성했습니다.

![동일 평가 조건에서 비교한 이상 탐지 결과](docs/assets/evaluation-comparison.svg)

## 해결하려는 문제

MVTec AD 2 Sheet-Metal 이미지는 가로로 긴 고해상도 영상입니다. 전체 이미지를 작은 정사각형으로 축소할 때 발생하는 **공간 정보 손실**이 미세 결함 탐지의 병목이 될 수 있습니다. 이 프로젝트는 다음 두 경로를 각각 구현하고, **같은 공개 시험 이미지 114장**, **같은 528×2112 이상 맵**, **같은 공식 평가기**로 결과를 비교합니다.

- **E2-Split 고해상도 추론**: EfficientAD로 원본을 256×256 타일 처리한 국소 이상 맵과 전체 장면의 전역 이상 맵을 결합합니다.
- **SuperADD / DINOv3 비교 경로**: 정상 이미지 특징을 메모리 뱅크로 구성하고 입력 특징과의 거리로 이상 영역을 찾습니다.

여기서 **256×256 기준선**은 전체 이미지를 한 장의 256×256 입력으로 축소한 EfficientAD 경로입니다. **E2-Split**은 같은 체크포인트를 다시 학습하지 않고 고해상도 분할 추론을 적용한 경로입니다.

## 실험 결과와 의미

| 검증 질문 | 관측 결과 | 해석 |
| --- | --- | --- |
| 고해상도 추론이 기준선보다 유효한가? | Image AU-ROC `0.595370 → 0.734722`, AU-PRO@0.05 `0.020582 → 0.132685` | 이 데이터에서는 전체 축소보다 국소·전역 정보를 보존한 추론 경로가 유리했습니다. |
| TensorRT/Triton 변환 후 성능이 유지되는가? | Image AU-ROC `0.734722 → 0.733333`, AU-PRO@0.05 `0.132685 → 0.132769` | 백엔드 변환이 정확도 개선 수단은 아니지만 근접한 평가 성능을 유지했습니다. |
| 다른 특징 방식은 어떤 결과를 내는가? | SuperADD: Image AU-ROC `0.839352`, AU-PRO@0.05 `0.431407` | DINOv3 특징과 정상 메모리 뱅크 경로를 같은 평가 조건에서 독립적으로 재현했습니다. |
| 차이는 어떤 결함에서 커지는가? | 면적 중간 구간의 평균 pixel AU-ROC 차이 `+0.206`, compactness 상관 `-0.773` | SuperADD의 상대적 위치화 우위가 중간 크기·덜 compact한 결함에서 커지는 경향이 있었습니다. 이 값은 관측된 상관입니다. |
| 실행 비용을 줄일 수 있는가? | 대표 이미지 E2E `2.4610 → 2.1040초` (`-14.5%`) | FP32 TensorRT plan, binary HTTP, 타일 배치 4가 적용된 실행 경로의 측정 결과입니다. |

**Image AU-ROC**는 이미지가 정상인지 이상인지 순위를 구분하는 지표이고, **AU-PRO@0.05**는 낮은 오탐 구간에서 결함 위치를 찾는 지표입니다. 모든 값은 TESTpub의 고정 원시 점수로 계산했으며 TESTpub은 학습·보정·임계값 선택에 사용하지 않습니다.

## 모델별 오류 차이

전체 지표만 보면 SuperADD가 높다는 사실만 남습니다. 동일 불량 이미지 90장의 이상 맵과 정답 마스크를 일대일로 비교하면 그 차이가 어디에서 발생했는지 볼 수 있습니다.

![동일 이미지의 이상 맵 차이를 결함 면적 구간별로 집계](docs/assets/paired-rawmap-analysis.svg)

- 결함 면적 낮음·중간·높음 구간의 평균 `SuperADD−E2-Split` pixel AU-ROC 차이는 각각 `+0.091`, `+0.206`, `+0.070`이었습니다.
- 개별 사례에는 E2-Split 우세 `-0.156`, 거의 동일 `-0.003`, SuperADD 우세 `+0.412`가 모두 있었습니다.
- 따라서 “한 모델이 항상 우수하다”가 아니라 **결함 조건에 따라 실패 특성이 다르다**는 것이 이 분석의 핵심입니다.

[분석 방법, 대표 이상 맵·정답 마스크 패널, 해석 한계](docs/PAIRED_RAWMAP_ANALYSIS.md)

## 구현한 파이프라인

1. **고해상도 분할 추론**
   256×256 타일의 국소 교사–학생 잔차를 Hann 가중치로 이어 붙이고, 전체 장면의 오토인코더–학생 잔차와 동결 분위수로 결합합니다.
2. **재현 가능한 평가 체계**
   체크포인트, 입력 목록, 원시 이상 맵, 평가 결과를 SHA-256으로 연결합니다. 실패·복구 증거도 원본 이미지나 로컬 경로 없이 기록합니다.
3. **TensorRT/Triton 실행 경로**
   FP32 TensorRT plan, Triton HTTP binary transport, 타일 배치 4, 최종 맵 parity와 TESTpub backend A/B를 검증했습니다.
4. **독립 모델 비교와 오류 분석**
   두 파이프라인의 동일 이미지 결과를 익명 ID로 연결해 픽셀 순위 성능과 결함 형상별 차이를 분석했습니다. 원본 제조 이미지는 공개하지 않습니다.

## 실행 구조

![고해상도 분할 추론과 TensorRT FP32 실행 흐름](docs/assets/system-architecture.svg)

EfficientAD 실행 경로는 입력 이미지 → 타일 분할 → TensorRT FP32/Triton 추론 → 타일 결합 → 원시 이상 맵 → 평가 순서입니다. SuperADD는 동일 평가 규약을 사용하는 별도 Python 추론 경로이며, 현재 TensorRT/Triton 실행 경로에는 포함하지 않았습니다.

## 결과를 해석할 때 주의할 점

검증 범위는 고정된 TESTpub 재현 비교와 EfficientAD 백엔드 변환입니다. 생산 배포, 다른 공정 데이터의 일반화, SOTA 비교에는 별도 검증이 필요합니다. 지연 수치는 EfficientAD 대표 이미지와 SuperADD 114장 분포처럼 측정 범위가 달라 직접 속도 비교하지 않습니다.

## 실행 방법

```bash
python3 -m pytest -q

export ARTIFACT_ROOT=/path/to/artifacts
export DATASET_ROOT=/path/to/dataset
PYTHONPATH=src python3 -m fine_defect_ad.highres_split infer --help
PYTHONPATH=src python3 -m fine_defect_ad.tensorrt_promotion --help
```

실제 추론에는 별도로 허가받은 데이터셋, 모델 가중치, 학습 체크포인트와 GPU 환경이 필요합니다. 대용량 원시 맵과 모델 파일은 별도 아티팩트 저장소에 둡니다. 필요한 입력과 산출물은 [재현 방법](docs/REPRODUCIBILITY.md)에 정리했습니다.
